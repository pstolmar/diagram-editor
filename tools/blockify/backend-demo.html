Blockers & Tickets Required
These are the real friction points that require action outside the engineering team. Plan for them at the start of the project.
🔒
PIM API Access from App Builder
App Builder actions run in Adobe's cloud. The PIM at internal.corp.net is behind corporate VPN — App Builder cannot reach it. Calling it from a cloud action simply times out.
Resolution path File an IT ticket to expose PIM via API Gateway or VPN peering to Adobe's outbound CIDR ranges. As a stopgap, cache product data in AEM and export via the CF Export API until the gateway is ready.
⏱ 2–4 weeks (IT provisioning) 🎫 IT ticket required
🔍
Elasticsearch Migration
The internal cluster at es-cluster.corp.net is unreachable from App Builder. The index also lives only on Author — search is currently unavailable on Publish even in the legacy setup.
Resolution path Three options: (a) migrate to Elastic Cloud (managed, publicly reachable), (b) use AEP Query Service as search backend, (c) rebuild with Algolia. Each carries different data migration and re-indexing scope.
⏱ 4–8 weeks 🎫 Architecture decision required
📡
Campaign IP Allowlisting
Adobe I/O App Builder uses a dynamic NAT gateway pool for outbound traffic. Campaign's existing allowlist entry for the static AEM Publish IP will not cover App Builder. Form submissions will be rejected by Campaign.
Resolution path Open a support ticket with the Adobe Campaign team to allowlist the App Builder NAT range — OR switch to Campaign's inbound webhook model (preferred, eliminates IP dependency entirely).
⏱ 5–10 business days 🎫 Adobe Support ticket
📋
Edge Worker Deployment: CAB Approval
New Edge Worker scripts on production Fastly require Change Advisory Board (CAB) approval at most enterprises. This is not a technical problem but a governance process that blocks production deployment. The CAB requires load-test evidence and a documented rollback plan before approving a production push. Starting this process late is the most common reason EDS migrations slip by 2–3 weeks.
Resolution path Stage in aem.live non-production first. Run load tests; capture P99 latency data. Submit the CAB request with test results and a rollback procedure (toggle Fastly VCL rule to bypass the worker).
⏱ 1–3 weeks (CAB cycle) 🎫 CAB request required
🔑
Kerberos / SSO Replacement
UserProfileService uses Kerberos auth — corporate-network-only, not replicable in cloud. The Identity team owns the replacement path and must be involved from day one.
Resolution path Switch to JWT-based segment tokens issued by the Identity service. Tokens are short-lived, edge-readable, carry only the segment data needed for personalization — no full profile transfer over the wire. Requires Identity team to build a token issuance endpoint.
⏱ 4–6 weeks 🎫 Identity team required
