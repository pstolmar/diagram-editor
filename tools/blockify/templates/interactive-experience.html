Frequently asked questions

Do I need AEM Cloud Service to use Edge Delivery Services?

No. The simplest EDS setup is GitHub + Fastly CDN with no AEM Author involved. Authors write content in Google Docs or Microsoft SharePoint, and a GitHub App syncs changes to the repo automatically. AEM Cloud Service is optional and only required when you want WYSIWYG authoring via the Universal Editor (XWalk mode).

Can I migrate only part of my site to EDS?

Yes — this is called the hybrid model. You configure your CDN to route specific paths (e.g., /content/legacy/*) to your existing AEM Publish instance while all other paths are served by EDS. The two origins share a single domain and CDN cache layer.

Most teams start with marketing pages (home, product, campaign) and migrate transactional or application areas last.

What happens to my existing Content Fragments?

Content Fragments remain in AEM and are served to EDS pages via the AEM Assets REST API or the CF Delivery (GraphQL) API. Your existing CF models and content do not change. EDS blocks fetch the CFs at runtime, so updates to CF content propagate to the live page as soon as AEM Publish replicates them.

How do I handle form submissions without AEM Forms?

EDS supports a spreadsheet-driven forms pattern where a Google Sheet or SharePoint document defines the form fields. Submissions are written back to the same sheet and can trigger email notifications via Power Automate or Google Apps Script.

For more complex scenarios (CRM integration, multi-step flows), use an App Builder microservice as the form submission endpoint.

Is server-side personalization possible on EDS?

Yes, via Akamai Edge Workers. You can inspect request headers (geolocation, device type, cookie segments) and serve different HTML variants before the response reaches the browser. For lighter-weight A/B testing, the EDS native Experimentation plugin routes variants client-side using the experiment page metadata field — no edge infrastructure required.
