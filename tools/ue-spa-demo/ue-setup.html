Universal Editor + React SPA — Setup Reference

Every mistake made, every gotcha hit, and the correct configuration that finally worked. Keep this page open next time UE breaks.

⚡ "Failed to fetch details" — fix it right now

Most common cause: IMS session expired.

  1. Open experience.adobe.com in the same browser — confirm you are logged in with the correct org
  2. Hard-refresh the UE page (Cmd+Shift+R)
  3. If that fails: check the CF path in data-aue-resource still exists in AEM Author Assets
  4. If CORS configs were wiped (RDE reset): run bash tools/fix-ue.sh (needs aio auth:login first)

→ Open debugue.html to diagnose CORS, IMS, and data attributes from the page itself.

1 — Required <meta> tags in every UE-editable page

These must be in the <head>. Without them UE cannot connect to the AEM author instance.

<!-- AEM author connection (system category, "aem" reference name matches urn:aem: in data-aue-resource) -->
<meta name="urn:adobe:aue:system:aem"
      content="aem:https://author-p138879-e1741192.adobeaemcloud.com">

<!-- UE CORS library — use adobe.io (experiencecloud.live/corslib/ is DEPRECATED as of March 2025) -->
<script src="https://universal-editor-service.adobe.io/cors.js" async></script>
CRITICAL The host meta tag must match EXACTLY

The host must be the full https://author-p…-e….adobeaemcloud.com URL — no trailing slash, no path. A typo here gives you a page that loads fine visually but the sidebar stays empty forever.

2 — Required data-aue-* attributes

Every editable container needs all of these. Missing even one silently breaks editing.

AttributeValue formatRequired on
data-aue-resourceurn:aem:/content/dam/…/jcr:content/data/masterContainer + field elements
data-aue-typecomponentContainer elements
data-aue-modelModel ID from component-models.jsonContainer elements
data-aue-labelHuman-readable nameContainer elements
data-aue-propCF field name (must match actual CF model)Individual field elements
CRITICAL data-aue-model is mandatory — its absence = empty Content Tree

This was the root cause of "Content Tree is empty / nothing is clickable." Without data-aue-model on the container, UE does not register it in the tree at all. The page loads fine in UE but you cannot select anything.

GOTCHA data-aue-prop values must match actual CF field names

CF field names are defined in the AEM Content Fragment model. Common PS Store CF fields: eyebrow, title, description, ctaLabel. Do not invent names — they silently fail.

Minimal working React helper pattern

// Container annotation — put this on the wrapper div
function aueRes(fragPath, label) {
  return {
    'data-aue-resource': 'urn:aem:' + fragPath,
    'data-aue-type': 'component',
    'data-aue-label': label || 'Content',
    'data-aue-model': 'hero',   // ← MUST match a model ID in component-models.json
  };
}

// Field annotation — put this on h1, p, etc.
function aueField(fragPath, prop, type, label) {
  return {
    'data-aue-resource': 'urn:aem:' + fragPath,
    'data-aue-prop': prop,      // ← MUST match actual CF field name
    'data-aue-type': type || 'text',
    'data-aue-label': label || prop,
  };
}

// CF path helper
function FRAG(slug, variation) {
  return '/content/dam/ue-demo/fragments/' + slug
       + '/jcr:content/data/' + (variation || 'master');
}

// Usage in JSX
<div {...aueRes(FRAG('summer-sale-hero'), 'Hero')}>
  <h1 {...aueField(FRAG('summer-sale-hero'), 'title')}>{data.title}</h1>
  <p  {...aueField(FRAG('summer-sale-hero'), 'description')}>{data.description}</p>
</div>

3 — component-models.json must define every model ID you use

UE fetches this from the site root. The id here must exactly match what you put in data-aue-model. Field name values here must match actual CF field names.

// component-models.json (served from site root)
[
  {
    "id": "hero",
    "fields": [
      { "component": "text",     "name": "eyebrow",     "label": "Eyebrow"      },
      { "component": "text",     "name": "title",       "label": "Title"        },
      { "component": "richtext", "name": "description", "label": "Description"  },
      { "component": "text",     "name": "ctaLabel",    "label": "CTA Label"    },
      { "component": "reference","name": "image",       "label": "Image", "multi": false }
    ]
  }
]
CRITICAL Never invent a model ID without adding it to this file

Using data-aue-model="ps-offer" when ps-offer does not exist in component-models.json causes UE to silently fail — no sidebar content, even though the Content Tree shows the component. Always add the model definition first.

GOTCHA This repo uses a build step to assemble the JSON

Run npm run build:json after editing anything in models/. The file component-models.json at the repo root is the assembled output — edit the source files in models/, not the root file directly.

4 — Correct URL format for opening a page in Universal Editor

https://experience.adobe.com/#/@workfrontcs/aem/editor/canvas/offers--diagram-editor--pstolmar.aem.live/tools/ue-spa-demo/newoffers.html
CRITICAL Do NOT include https:// in the page path inside the hash

Browsers normalize https:// → https:/ inside URL hash fragments. If you write:

...#/@org/aem/editor/canvas/https://offers--...aem.live/tools/...

UE loads https://https:/offers--...aem.live which 404s. The page path after /canvas/ must be just the host and path, no protocol.

5 — CORS on the AEM author instance

UE at experience.adobe.com makes XHR requests to your author. The author must return CORS headers allowing https://experience.adobe.com.

The CORS OSGi config package for this project lives at: tools/cors/. Deploy with:

aio aem:rde:install tools/cors/ui.config-1.0-SNAPSHOT.zip -t content-package
GOTCHA Rapid Development Environment (RDE) only

This deploy command targets the RDE. Production/stage environments need the package deployed via Cloud Manager pipeline.

6 — CDN propagation delay

GOTCHA 30–60 seconds after git push before changes are live

After git push origin offers, wait ~60 seconds before testing. Hard-refresh in UE (⌘+Shift+R) after the wait. Loading immediately after push will show the old version and make it look like your fix didn't work.

7 — ?date= simulation pattern for demo countdown

To demo a page "as of" a future date while keeping the countdown ticking in real time:

// Capture real wall-clock time at page load
var SIM_REAL_START = Date.now();

// Parse ?date=YYYYMMDD from URL
var SIM_DATE = (function() {
  var m = location.search.match(/[?&]date=(\d{8})/);
  if (!m) return null;
  var s = m[1];
  return new Date(s.slice(0,4)+'-'+s.slice(4,6)+'-'+s.slice(6,8)+'T00:00:00Z');
})();

// In countdown hook — offset sim date by elapsed real time
function useCountdown(expiryISO, simNow) {
  function compute() {
    // If simNow provided, advance it by however much real time has passed
    var now = simNow
      ? simNow.getTime() + (Date.now() - SIM_REAL_START)
      : Date.now();
    var diff = new Date(expiryISO).getTime() - now;
    // ... compute d/h/m/s from diff
  }

  useEffect(function () {
    // ← DO NOT add "if (simNow) return;" here — that freezes the countdown
    function tick() { setParts(compute()); }
    tick();
    var id = setInterval(tick, 1000);
    return function () { clearInterval(id); };
  }, [expiryISO]);
}
CRITICAL Never add "if (simNow) return" inside useEffect

Adding an early return when simNow is truthy prevents the setInterval from running, which freezes the display at whatever value it had on mount. Remove it and offset with SIM_REAL_START instead.

8 — Things that look helpful but break everything

CRITICAL Do NOT switch data fetches to AUTHOR inside UE

It seems logical: UE saves to author, so fetch from author to see edits live. Do not do this. The SPA origin (offers--diagram-editor--pstolmar.aem.live) is not in the AUTHOR CORS allowlist, so every fetch silently fails and React falls back to hardcoded placeholder data. The page looks broken. The CF data was never gone — the fetch just failed.

The correct flow: fetch always from PUBLISH. Edit in UE sidebar. UE previews the change on canvas as you type. When done, click Publish in UE — this publishes the CF variant and the live page reflects it immediately.

CRITICAL Do NOT re-fetch hero/offers on aue:content-patch

Adding re-fetches of hero and offer CFs after every UE save causes the same CORS failure → placeholder data problem. The ghost variants re-fetch (already in the original code) is fine because it targets the same PUBLISH endpoint with no auth issues. Only re-fetch ghost variants on aue:content-patch.

GOTCHA UE canvas "live preview" is not a re-fetch

When you type in the UE sidebar, the canvas updates immediately. This is UE's own DOM patching — it is NOT a re-fetch from the CF. Do not confuse this as proof that author fetches are working. The real test is: publish the CF, reload the page, confirm the value shows.
