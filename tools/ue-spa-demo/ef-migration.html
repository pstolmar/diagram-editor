Key differences explained

Three patterns cover 95% of AEM-to-EDS migrations. Each can be done independently.

⬡

Experience Fragments → Blocks

XF (before)
  • Stored in /content/experience-fragments/
  • Server-rendered by AEM Sling/HTL
  • Tightly coupled to component hierarchy
  • 47+ component tree for a simple nav
  • Requires full AEM publish stack
Block (after)
  • HTML table in Word or DA document
  • Decorated by JS in the browser
  • One JS + one CSS file per block
  • Zero AEM render dependency
  • Cached at edge — sub-100ms TTFB
Migration path Export XF HTML → paste into Word → create block table → commit block JS/CSS
⨸

Content Fragments stay (but get simpler)

CF via page (before)
  • CF referenced inside AEM page tree
  • Resolved at Sling render time
  • HTL templates embed CF data inline
  • No direct API access from browser
  • UE edits require AEM page context
CF via GraphQL (after)
  • Same CF, same data model — no migration
  • Block fetches via /api/graphql
  • CF becomes truly headless
  • UE edits via data-aue-* attributes
  • Works in any framework or none
Migration path Keep CF as-is → switch block to fetch(/graphql) → add data-aue-* attributes
●

Structured Content (new)

XF promos (before)
  • Promo banner stored as XF in AEM
  • 15 components for a 2-field banner
  • Marketers need AEM author access
  • Full publish workflow for every edit
  • AEM infrastructure required at delivery
DA Structured Content (after)
  • Schema-driven form in Document Authoring
  • JSON delivered via Worker API
  • Marketers edit in browser — no AEM login
  • Live in seconds, no publish step
  • Zero AEM dependency for delivery
Migration path Define DA schema → create Worker → replace XF reference with fetch(worker/promo)
↻

This migration can be done incrementally — one component at a time, one page at a time. You don’t need to migrate everything at once.

Start with your footer XF (fewest dependencies), then tackle individual teasers and promo banners. Each block you migrate independently reduces AEM infrastructure load and improves real-user page performance — you see measurable gains from the very first block.
