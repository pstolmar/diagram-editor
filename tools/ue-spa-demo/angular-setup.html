Angular + AEM Universal Editor · Setup Guide

The errors you will see, what they mean, and exactly how to fix them

1 — Architecture Overview

  • The Angular app fetches CF data from AEM Publish via GraphQL persistent queries — always Publish, never Author.
  • Universal Editor edits fields on AEM Author — the page just needs data-aue-* attributes in the rendered HTML to declare what is editable.
  • The app does not need to live on EDS — any publicly reachable Angular URL works with UE as long as the required <meta> tags and CORS config are in place.

2 — Minimum Setup Checklist

All four must be in place before UE will function. None of them produce obvious error messages when missing — they just silently do nothing.

  • <meta name="urn:adobe:aue:system:aem" content="aem:https://your-author.adobeaemcloud.com"/> in <head> — tells UE which Author instance owns this page.
  • <script src="https://universal-editor-service.adobe.io/cors.js" async></script> in <head> — loads the UE client-side bridge that handles postMessages and auth.
  • CORS + Bearer auth OSGi configs deployed to AEM Author. Packages live at tools/cors/. See Section 7 for deploy commands.
  • data-aue-resource, data-aue-type, data-aue-prop, and data-aue-label on each editable element in the Angular template.

3 — Critical Rules

Critical NEVER add data-aue-model to a container element

When data-aue-model is present on a container, UE calls the /details API endpoint to look up the component model definition. This returns HTTP 500 unless the model ID is registered in component-models.json and that file is served from your site root. For Content Fragment editing in a standalone Angular SPA, omit data-aue-model entirely — UE reads field structure from the CF model directly.

Critical ALWAYS fetch CF data from Publish, never Author

Your SPA's origin (e.g. your-app.aem.live or localhost:4200) is not in the Author CORS allowlist for data fetches. Fetching from Author silently fails — Angular catches the error and falls back to placeholder data, making it appear the CF is empty or broken. Use GraphQL persistent queries on the Publish URL at all times.

Critical NEVER create Content Fragments via vault packages

The JCR structure for a Content Fragment contains undocumented required fields (cq:name, contentFragment=true, proper mixins, CF metadata nodes). A vault package that omits any of them produces a node that silently fails in the CF REST API — UE cannot read or write it, and it may not even appear in the Assets UI. Always copy an existing working CF in AEM Author Assets UI.

Required Add the UE postback message listener

After the author saves a field in UE, it sends a aue:content-patch or aue:content-update postMessage to the page frame. Without a listener, the Angular component never re-fetches and keeps showing the old content.

// Add once in your root Angular component (ngOnInit or constructor)
window.addEventListener('message', (e) => {
  if (
    e.data?.type === 'aue:content-patch' ||
    e.data?.type === 'aue:content-update'
  ) {
    setTimeout(() => this.fetchFromPublish(), 600);
  }
});

The 600 ms delay lets AEM Publish replicate the change before the fetch fires.

4 — If you see this → it means → fix it this way

Each block below is one failure pattern. Red = what you see. Yellow = why it happens. Green = exact fix.

If you see this
Failed to fetch details
Request ID: xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx
URL: https://universal-editor-service.adobe.io/details
Backend responded with: 500
It means

(a) data-aue-model is present on a container element — UE tries to resolve the component model definition from your site's /component-models.json and 500s when the model ID isn't registered there.

(b) Alternatively, the Author CORS config is missing or doesn't include your SPA's origin, so UE's /details request is rejected.

Fix it this way

(a) Remove data-aue-model from all container elements in your Angular template. For CF-based editing, UE derives the field list from the CF model automatically.

(b) Deploy the CORS config with alloworiginregexp: ["https://.*\\.aem\\.live", "https://experience\\.adobe\\.com"] and the Bearer auth config to AEM Author (see Section 7).

If you see this
Backend responded with: 500
{
  "title": "Internal Server Error",
  "detail": "Cannot invoke \"String.length()\" because \"name\" is null"
}
URL: https://author-.../adobe/sites/cf/fragments?path=/content/dam/.../my-fragment
It means

The Content Fragment was created via a vault package with an incomplete JCR structure. The cq:name property is missing from jcr:content (and possibly other required metadata). The CF REST API — which UE calls to read and write field values — cannot parse the node and throws a null-pointer exception.

Fix it this way

Delete the malformed fragment from the JCR. In AEM Author Assets UI, navigate to /content/dam/your-project/fragments/, find a working fragment with the same model, and use Copy → Paste to create a new one at the correct path. Open the new fragment in the CF editor, fill in the fields, then Quick Publish. Never use vault packages to create CFs.

If you see this
Backend responded with: 500
{
  "title": "Internal Server Error",
  "detail": "The server encountered an unexpected error."
}
URL: https://author-.../adobe/sites/cf/fragments?path=/content/dam/.../my-fragment
It means

Same root cause as Error 2 — a vault-package CF with a malformed JCR structure. A different code path in the CF REST API hits the same bad node and produces a more generic 500 message instead of the null-pointer detail.

Fix it this way

Identical fix: delete the fragment, copy a working one in Assets UI, populate fields in the CF editor, Quick Publish. The error message variant doesn't change the solution — it's the same JCR corruption.

If you see this
IMS Client ID not allowlisted.
Allowlist the Client ID using the Configuration Pipeline.
Client ID: aio-cli-console-auth
It means

You (or an automation script) tried to call the AEM CF OpenAPI (/adobe/sites/cf/fragments) via the aio CLI. The client ID aio-cli-console-auth is not allowlisted for this API — that allowlist requires an entry pushed through the AEM Configuration Pipeline, not a runtime config.

Fix it this way

Use AEM Author Assets UI to create and manage Content Fragments. The CF OpenAPI is not accessible via aio CLI in this configuration. If programmatic access is required, it must go through the Configuration Pipeline allowlist process — which is out of scope for a demo setup.

If you see this behavior

You edited a field in Universal Editor and clicked Publish, but the Angular page still shows the old content after refreshing.

It means

The UE postback message listener is missing from the Angular component. After saving, UE sends a aue:content-patch postMessage to the page frame. Without a handler, Angular never knows a save occurred and never re-fetches from Publish.

Fix it this way

Add the listener in ngOnInit() of your root component (or whichever component owns the CF data):

ngOnInit(): void {
  window.addEventListener('message', (event) => {
    if (
      event.data?.type === 'aue:content-patch' ||
      event.data?.type === 'aue:content-update'
    ) {
      // 600ms delay — lets Publish replicate before we fetch
      setTimeout(() => this.loadFragmentData(), 600);
    }
  });
  this.loadFragmentData(); // initial load
}
If you see this behavior

You installed a vault package containing a Content Fragment, but the fragment doesn't appear in AEM Author Assets UI (or appears as a regular asset, not a CF).

It means

AEM uses several JCR properties and mixins to identify a node as a Content Fragment: contentFragment=true on jcr:content, the dam:ContentFragment mixin, cq:model pointing to the correct model path, cq:name set on the content node, and proper dc:title in the metadata node. A vault package assembled by hand or by exporting from a different environment commonly misses at least one of these, causing silent failure — AEM either hides the node or displays it as a generic DAM asset.

Fix it this way

Copy approach, always. In Assets UI: navigate to a working CF of the same model → select it → Copy → navigate to target folder → Paste → rename. This guarantees all required JCR properties are present because AEM generates them. Never hand-craft CF vault packages.

If you see this behavior

The UE Properties panel (right sidebar) shows no editable fields when you click a component in the Content Tree.

It means

Either data-aue-prop attributes are missing from the individual field elements, or the data-aue-resource on those fields doesn't match the parent container's resource, or the data-aue-type on fields is missing. UE uses the combination of resource + prop + type on each DOM element to build the Properties panel — any one missing and the field silently disappears from the panel.

Fix it this way

Every field element needs all four attributes. Inspect the DOM in DevTools and confirm:

<!-- Container -->
<div
  [attr.data-aue-resource]="res"
  data-aue-type="component"
  data-aue-label="Hero">

  <!-- Each editable field — resource must match container -->
  <h1
    [attr.data-aue-resource]="res"
    data-aue-prop="title"
    data-aue-type="text"
    data-aue-label="Title">
    {{ fragment.title }}
  </h1>

  <p
    [attr.data-aue-resource]="res"
    data-aue-prop="description"
    data-aue-type="richtext"
    data-aue-label="Description">
    {{ fragment.description }}
  </p>
</div>

The res property is the full urn:aem:/content/dam/.../jcr:content/data/master string — same value on both container and fields.

5 — UE Attribute Quick Reference

Attribute Where to put it Value
data-aue-resource Container + every field urn:aem:/content/dam/.../jcr:content/data/master
data-aue-type Container element component
data-aue-type Plain text field text
data-aue-type Rich text / HTML field richtext
data-aue-type Image field image
data-aue-prop Every field element CF field name, e.g. eyebrow, title, ctaLabel
data-aue-label Every field element Human-readable label shown in UE Properties panel
Note Do NOT add data-aue-model

Unless you have a component-models.json served from the app root with a matching model ID, omit data-aue-model. Its presence triggers a /details lookup that 500s when the model isn't registered. For CF-based editing in a standalone SPA, it is not required.

6 — Fragment Path Pattern

The data-aue-resource value must point to the content data node, not the fragment root. Using the root path causes UE to find the fragment but not the editable fields.

// Angular service helper

const FRAG_PATH = '/content/dam/ue-demo/fragments/my-fragment';

// CORRECT — /jcr:content/data/master
const RES = 'urn:aem:' + FRAG_PATH + '/jcr:content/data/master';

// WRONG — fragment root path: UE finds the node but misses the fields
const RES_WRONG = 'urn:aem:' + FRAG_PATH;

// In the Angular component template:
// <div [attr.data-aue-resource]="res" data-aue-type="component" data-aue-label="Hero">

For a named variation instead of master:

const RES_VARIANT = 'urn:aem:' + FRAG_PATH + '/jcr:content/data/my-variation';

7 — RDE Config Deploy Commands

Deploy CORS and Bearer auth configs to AEM Author RDE:

aio aem:rde:install tools/cors/ui.config-ue-cors-1.0.zip --target author
aio aem:rde:install tools/cors/ui.config-ue-bearer-1.0.zip --target author
Gotcha RDE only — Cloud Manager required for stage/prod

These commands target the Rapid Development Environment. Deploying to stage or production requires the package to go through the Cloud Manager pipeline.

Gotcha If UE breaks after an RDE reset

RDE state does not persist across resets. If the Properties panel stops working or you see 403s from Author, the OSGi configs were wiped. Re-run both install commands above and wait ~30 seconds for the configs to activate before retesting.
