The Moment

This Is the Migration Window

Three platform-level changes make 2025–2026 the right time to move. Waiting is a choice, but it's not a free one.

warning
SPA Editor is Deprecated
Adobe officially deprecated AEM SPA Editor in 2024. If your site is built on MapTo() and @adobe/aem-react-editable-components, you're on a dead-end path. Universal Editor is the replacement — and it works with EDS.
schedule
Core Components → Maintenance Mode
AEM Core Components are entering maintenance mode. New feature investment is in EDS blocks. Sites built on Core Components will continue to work — but the momentum is elsewhere.
trending_up
Your Competitors Are Already There
EDS customers regularly report 95+ Lighthouse scores and sub-second LCP. Slow pages mean lower conversion, worse SEO, higher bounce rate. The performance gap is visible to customers.
The Path

You Don't Have to Migrate Everything at Once

EDS migration is additive. Each step ships independently. You never flip a big-bang switch — you run edge delivery alongside AEM Sites until the balance tips.

1
Audit  (1 day)
List your XFs, Core Components, and custom components. Map each to an EDS block equivalent. Identify which ones hit backend APIs.
2
Start with the footer  (1 afternoon)
Your footer XF has the fewest dependencies. One JS + CSS file replaces 23 components. First CDN cache hit: instant.
3
Migrate static XFs  (1–2 weeks)
Nav, promo banners, page headers. No backend data. Word table → block in an afternoon. Each one reduces AEM Publish load.
4
Data-driven components  (varies)
Custom components calling backends become Cloudflare Workers + block fetch(). Same API, live data in the browser, no AEM in the path.
5
Flip the switch
Once delivery is edge-cached blocks, AEM Publish is no longer in your critical path. Authors still use the same tools — UE or Word/DA.
❌"We'd have to retrain our authors"
✓Authors use the same Universal Editor, or Word/SharePoint they already know.
❌"We'd lose our Content Fragments"
✓CFs survive unchanged — same data model, now served headlessly via GraphQL.
❌"Our custom components are too complex"
✓Complex Java OSGi services become small serverless Workers. The block code is trivial.

Try It Yourself

Deploy the full demo to your own AEM Cloud Service RDE in under 5 minutes — no repo clone needed.

prereq aio CLI installed & authenticated to your AEM Cloud org npm i -g @adobe/aio-cli && aio login && aio aem rde setup
1 Download the packages
ui.config-ue-cors-1.0.zip Universal Editor CORS config — Author
↓ Download
ui.config-ue-bearer-1.0.zip Bearer token auth for UE — Author
↓ Download
ui.config-clickjacking-publish-1.0.zip Remove X-Frame-Options so page embeds in iframes — Publish
↓ Download
ui.content.core-showcase-1.0.zip Demo page with Core Components + XF — Author content
↓ Download
ui.apps.core-showcase-theme-1.0.zip Minimal CSS clientlib so Core Components render — Author + Publish
↓ Download
ui.content.home-hero-cf-1.0.zip home-hero Content Fragment for UE editing demo — Author
↓ Download
setup-cf.sh Alt: shell script that creates the CF via Sling POST — auto-detects model path
↓ Download
2 Install to your RDE
aio aem rde install ~/Downloads/ui.config-ue-cors-1.0.zip -s author UE CORS — Author
aio aem rde install ~/Downloads/ui.config-ue-bearer-1.0.zip -s author Bearer auth — Author
aio aem rde install ~/Downloads/ui.config-clickjacking-publish-1.0.zip -s publish Iframe embedding — Publish
aio aem rde install ~/Downloads/ui.content.core-showcase-1.0.zip -s author Demo page — Author (then publish via Author UI)
aio aem rde install ~/Downloads/ui.apps.core-showcase-theme-1.0.zip CSS clientlib — Author + Publish
aio aem rde install ~/Downloads/ui.content.home-hero-cf-1.0.zip -s author home-hero CF — Author (then Quick Publish in Assets UI)
3 If the CF package fails

The CF package uses /conf/glass-facades/settings/dam/cfm/models/home-hero as the model path. If your AEM conf differs, use the script instead — it auto-detects the right path from any sibling fragment:

chmod +x ~/Downloads/setup-cf.sh && ~/Downloads/setup-cf.sh https://author-<env>.adobeaemcloud.com Requires aio login first
